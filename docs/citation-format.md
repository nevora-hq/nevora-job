# 出典フォーマット仕様(sources)

2026-08-10に新設。記事frontmatterの `sources` フィールドで出典を構造化して管理する仕様。実装は `lib/articleMeta.js`(このサイトには無い。読まずに進める)(`normalizeSources`)・`components/ArticleSources.js`。

## 背景

多数の記事が出典として「トップページURL」「副業系メディア・比較サイトのランキング記事」「スクール・情報商材・ASPの宣伝ページ」だけを引用し、一次情報(国税庁・厚生労働省・金融庁・消費者庁などの公的機関、e-Gov法令検索の条文、政府統計、業界団体、サービス提供元〔クラウドソーシング・ASP等〕の公式ヘルプ・規約)が不足する状態を防ぐための仕様である。従来の出典は本文末尾の「## 出典一覧」見出し+自由形式Markdownリンクのみで、一次/二次の区別・URLの深さ・編集部独自調査であることの明示が構造化されていなかった。

この仕様は、出典の弱さの再発をコード側で検知しやすくすることと、新規記事が最初から一定水準の出典を持つことを目的とする。

## 出典の決まり

何を出典にするか(一次情報だけ・出典にしないもの・必須でないこと・確認できないものは使わない・適用範囲)は `.claude/agents/writer.md` の「出典の決まり」と規則34が正。この文書は書式と検証の手順だけを置く。以下のスキーマのうち `secondary` と `editorial` は、既存記事に残るものを表すためのもので、新規・書き直しの記事では使わない(下の「type の使い分け」)。サービスを売る事業者のページ(副業スクール・講座・案件紹介業者など)の扱いも writer.md「出典の決まり」が正で、ここには写さない。

## frontmatterスキーマ

```yaml
sources:
  - label: "国税庁 No.1900 給与所得者で確定申告が必要な人"
    url: "https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1900.htm"
    type: "primary"
```

### フィールド

| フィールド | 必須 | 説明 |
|---|---|---|
| `label` | 必須 | 出典の表示名(サイト名・調査名など) |
| `type` | 必須(`sources` を置くとき) | 新規・書き直しの記事は `primary`(一次情報)だけ。`secondary`(二次情報)・`editorial`(編集部調査)は既存記事に残るものを表す型 |
| `url` | `primary`/`secondary`で必須 | 該当ページの**深いURL**(トップページのみは警告対象。判定は「pathnameが空または`/`のみ」の簡易チェック) |
| `surveyN` | `editorial`(既存記事に残るもの)で必須 | 調査のn数(サンプル数) |
| `surveyMethod` | `editorial`(既存記事に残るもの)で必須 | 調査方法(例:「アンケート」「編集部内ヒアリング」) |
| `surveyDate` | `editorial`(既存記事に残るもの)で必須 | 実施時期(例:「2026-08」) |

### type の使い分け

- **primary(一次情報)**: 情報の一次発信元。範囲は writer.md「出典の決まり」を見る。
- **secondary(二次情報)**: 既存記事に残るもの(書式は `url` と `label` が `primary` と同じ)。新規・書き直しでは使わない。
- **editorial(編集部調査)**: 既存記事に残るもの(`surveyN`・`surveyMethod`・`surveyDate` を持つ)。署名は実名の運営者に結び付くので、運営者が実際には行っていない調査・確かめていない数値を editorial として載せない。n数等が記録に無く明記できないものは、`sources` に載せず本文でも「筆者調べ」等の表現を使わない(削除するか、明記できる形に調べ直す)。新規・書き直しでは使わない。

## バリデーション(ビルド時警告)

`lib/articleMeta.js`(このサイトには無い。読まずに進める) の `normalizeSources` が以下をチェックし、違反時は `next build`/`next dev` のログに `console.warn` を出す(**ビルドは失敗させない**。記事データはMarkdownで人手管理のため、軽微な入力漏れでビルド全体を止めると運用の障害になるため)。

- `label` が空
- `type` が `primary`/`secondary`/`editorial` 以外(未指定含む)→ コードは `secondary` 扱いにフォールバックして警告を出す(新規・書き直しでは `primary` を明示する)
- `primary`/`secondary` で `url` が空、またはトップページ相当(浅いURL)
- `editorial` で `surveyN` / `surveyMethod` / `surveyDate` のいずれかが空

## 表示

`components/ArticleSources.js` が `post.sources` を受け取り、記事末尾(悩みチップの後、参考情報の明記の前)に「出典」見出し+リストとして描画する。`type` ごとにバッジ(一次情報/二次情報/編集部調査)を表示する。`sources` が空配列の記事ではコンポーネントは何も描画しない。

## 既存記事(本文「## 出典」セクション)との関係

(2026-10-11 追記)読者に見える本文に「出典:…」を出さない決まり(依頼者の決定。原文:「毎回出典を記載するの禁止。記事末にある出典のみにすること。」)が正。出典は記事末の「出典」欄(`sources`)に載せる(ただし図表の下の「出典:」は対象外で、図の一部として残す。2026-10-11 依頼者の決定:「図表に関しては、図の下に入れる形で良いです。」)。`%%出典:…%%` の印は作業上の印で、原稿に残してよい。サイトのコード(`lib/posts.js` の `removeSourceCitationMarks`)が本文の印を描画時に取り除き、読者の画面には出ない。印の置き方は writer.md「伝聞と出典の書き方」が正。以下の既存記事の扱いは、この決まりを減らすものではない。

**一斉移行はしない。** `sources` が設定されているのは移行した記事のみで、それ以外の記事は従来通り本文中の「## 出典」見出し+Markdownリンクがそのまま表示される(後方互換)。

- `sources` が設定された記事は、本文側の「## 出典」セクションを**削除すること**(残すと出典が二重表示される)。
- 削除を忘れた場合、`lib/posts.js` の `getPostBySlug` が `sources` と本文の `## 出典`/`### 出典` 見出しの共存をビルド時に検知し、`console.warn` で警告する(自動では本文側を削除しない。正規表現によるHTML分割はB1/B2と同種の不具合を招くリスクがあるため)。

## 出典の検証基準(標準ルール)

出典を付けるとき(出典は必須ではない。付ける文の線は writer.md 規則11(6)が正)は、次の2段階を両方満たすこと。**「URLが実在する」ことと「そのURLが記述内容の根拠になる」ことは別物であり、前者だけでは出典として不十分。**

1. **実在確認**: URLが実在し、リンク切れでないこと(WebSearch等で確認)。
2. **裏付け確認**: そのページの内容が、記事本文の当該記述を実際に裏付けているか(組織のトップページ・関連ページというだけで、記述内容そのものには触れていない、ということがないか)を確認すること。

裏付け確認の結果に応じて、以下のいずれかで対応する。

- **完全に裏付ける** → そのまま`primary`として採用。
- **部分的にしか裏付けない**(例:出典1件で2つの主張をカバーしようとしていたが、片方しか支持しない) → 出典を分割し、それぞれが実際に裏付ける範囲だけをラベルに明記する。
- **裏付けを直接確認できない**(検索がJavaScript駆動で結果を直接確認できない等) → 出典として使わない(既存記事に残る格下げ済みの出典は、書き直すときに外す)。実在すら確認できない場合も使わない。

副業の題材での当てはめ(作例): 国税庁の「No.1900 給与所得者で確定申告が必要な人」1件で、「給与所得者で給与以外の所得が20万円以下なら確定申告は不要(条件あり)」と「その場合も住民税の申告は必要」の2つを支えようとする、という状況を考える。このページは所得税の確定申告が必要な人の条件を扱っており、住民税の申告には触れていない。この場合は「部分的にしか裏付けない」に当たるので、国税庁のページは前者だけを支える出典とし、後者は住民税を扱う市区町村等のページを別の出典として立てる。

## 声(SNS・知恵袋など)は出典にしない

悩みを探すために読んだ声(`voices.md`。規則34)は、出典にも、答えの根拠・数字の裏付けにもしない。`sources` にも図表の `source` にも載せない。使い道は規則34(e)が正。

## 移行方針

- 移行は求めない。内容修正で `sources` を置くときだけ、この形式にする(期限は設けない)。
- 新規記事は、出典が要る文(`.claude/agents/writer.md` の規則11(6) の線)があるときだけ `sources` を置く。
