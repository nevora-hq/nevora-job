# 出典フォーマット仕様(sources)

2026-08-10に新設。記事frontmatterの `sources` フィールドで出典を構造化して管理する仕様。実装は `lib/articleMeta.js`(`normalizeSources`)・`components/ArticleSources.js`。

## 背景

多数の記事が出典として「トップページURL」「副業系メディア・比較サイトのランキング記事」「スクール・情報商材・ASPの宣伝ページ」だけを引用し、一次情報(国税庁・厚生労働省・金融庁・消費者庁などの公的機関、e-Gov法令検索の条文、政府統計、業界団体、サービス提供元〔クラウドソーシング・ASP等〕の公式ヘルプ・規約)が不足する状態を防ぐための仕様である。従来の出典は本文末尾の「## 出典一覧」見出し+自由形式Markdownリンクのみで、一次/二次の区別・URLの深さ・編集部独自調査であることの明示が構造化されていなかった。

この仕様は、B3(出典の弱さ)の再発をコード側で検知しやすくすることと、記事自動生成プロンプトの改訂後の新規記事が最初から一定水準の出典を持つことを目的とする。

## frontmatterスキーマ

```yaml
sources:
  - label: "国税庁 No.1900 給与所得者で確定申告が必要な人"
    url: "https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1900.htm"
    type: "primary"
  - label: "◯◯新聞 解説記事"
    url: "https://example-news.jp/article/xxxx"
    type: "secondary"
  - label: "編集部調査"
    type: "editorial"
    surveyN: 20
    surveyMethod: "アンケート(NEVORA読者)"
    surveyDate: "2026-08"
```

### フィールド

| フィールド | 必須 | 説明 |
|---|---|---|
| `label` | 必須 | 出典の表示名(サイト名・調査名など) |
| `type` | 必須 | `primary`(一次情報) / `secondary`(二次情報) / `editorial`(編集部調査)のいずれか |
| `url` | `primary`/`secondary`で必須 | 該当ページの**深いURL**(トップページのみは警告対象。判定は「pathnameが空または`/`のみ」の簡易チェック) |
| `surveyN` | `editorial`で必須 | 調査のn数(サンプル数) |
| `surveyMethod` | `editorial`で必須 | 調査方法(例:「アンケート」「編集部内ヒアリング」) |
| `surveyDate` | `editorial`で必須 | 実施時期(例:「2026-08」) |

### type の使い分け

- **primary(一次情報)**: 公的機関(国税庁・厚生労働省・金融庁・消費者庁・国民生活センター等)・法令の条文(e-Gov法令検索)・政府統計・学会・論文・業界団体・サービス提供元の公式(クラウドソーシング・ASP・証券会社等の公式ヘルプ・規約)など、情報の一次発信元。ただし、副業スクール・講座・コンサル・案件紹介業者など有料のサービスを売る事業者の公式ページは、その事業者自身の料金・期間・契約条件(解約・返金の条件を含む)を書くときだけ使い、収入・成果の見込みの裏付けには使わない(`.claude/agents/writer.md` の出典ヒエラルキー)。
- **secondary(二次情報)**: 大手メディア(実績のある編集体制を持つ新聞・出版社等)の解説記事など、一次情報を紹介・解説している情報源。個別の事務所の集客コラム・副業スクールや情報商材の販売ページ・アフィリエイトサイト・比較/ランキングサイトは、`.claude/agents/writer.md` の出典ヒエラルキーで原則使用禁止なので secondary としても載せない。一次情報が別途無い場合の補助として使う。
- **editorial(編集部調査)**: NEVORA編集部(記事の署名は「NEVORA編集部(運営者: 眞井 虹輝)」。運営者情報は /about に氏名を掲載)が独自に行った調査・ヒアリング・試算。署名は実名の運営者に結び付くので、運営者が実際には行っていない調査・確かめていない数値を editorial として載せない。非公式調査であっても「編集部調査(n数・調査方法・実施時期を明記)」として正直にラベリングすれば独自データとしての強みになる、という考え方に基づく。n数等が記録に無く明記できない場合は、この`sources`に載せず本文中で「筆者調べ」等の表現も使わない(削除するか、明記できる形に調べ直す)。

**primary/secondaryの区分基準の補足(2026-08-11追加)**: 「本文中で直接引用しているかどうか」と「一次情報か二次情報か」は独立した属性であり、混同しないこと。一次情報とは情報の発生源(サービス提供元の公式・公的機関・法令・査読論文・編集部が自ら実施した調査)を指す。新聞・出版社等の編集メディアは、本文中で直接引用していても情報の発生源ではないためsecondaryのままである。

## バリデーション(ビルド時警告)

`lib/articleMeta.js` の `normalizeSources` が以下をチェックし、違反時は `next build`/`next dev` のログに `console.warn` を出す(**ビルドは失敗させない**。記事データはMarkdownで人手管理のため、軽微な入力漏れでビルド全体を止めると運用の障害になるため)。

- `label` が空
- `type` が `primary`/`secondary`/`editorial` 以外(未指定含む)→ `secondary` 扱いにフォールバック
- `primary`/`secondary` で `url` が空、またはトップページ相当(浅いURL)
- `editorial` で `surveyN` / `surveyMethod` / `surveyDate` のいずれかが空

## 表示

`components/ArticleSources.js` が `post.sources` を受け取り、記事末尾(悩みチップの後、参考情報の明記の前)に「出典」見出し+リストとして描画する。`type` ごとにバッジ(一次情報/二次情報/編集部調査)を表示する。`sources` が空配列の記事ではコンポーネントは何も描画しない。

## 既存記事(本文「## 出典」セクション)との関係

(2026-10-11 追記)読者に見える本文に「出典:…」を出さない決まり(依頼者の決定。原文:「毎回出典を記載するの禁止。記事末にある出典のみにすること。」)が正。出典は記事末の「出典」欄(`sources`)に載せる(ただし図表の下の「出典:」は対象外で、図の一部として残す。2026-10-11 依頼者の決定:「図表に関しては、図の下に入れる形で良いです。」)。`%%出典:…%%` の印は作業上の印で、原稿に残してよい。サイトのコード(`lib/posts.js` の `removeSourceCitationMarks`)が本文の印を描画時に取り除き、読者の画面には出ない。以下の既存記事の扱いは、この決まりを減らすものではない。

**一斉移行はしない。** 既存記事のうち、`sources` が設定されているのは今後の記事修正のついでに移行した記事のみで、それ以外の記事は従来通り本文中の「## 出典」見出し+Markdownリンクがそのまま表示される(後方互換)。

- `sources` が設定された記事は、本文側の「## 出典」セクションを**削除すること**(残すと出典が二重表示される)。
- 削除を忘れた場合、`lib/posts.js` の `getPostBySlug` が `sources` と本文の `## 出典`/`### 出典` 見出しの共存をビルド時に検知し、`console.warn` で警告する(自動では本文側を削除しない。正規表現によるHTML分割はB1/B2と同種の不具合を招くリスクがあるため)。

## 出典の検証基準(標準ルール、2026-08-10確定)

出典URLを追加・移行する際は、次の2段階を必ず両方満たすこと。**「URLが実在する」ことと「そのURLが記述内容の根拠になる」ことは別物であり、前者だけでは出典として不十分。**

1. **実在確認**: URLが実在し、リンク切れでないこと(WebSearch等で確認)。
2. **裏付け確認**: そのページの内容が、記事本文の当該記述を実際に裏付けているか(組織のトップページ・関連ページというだけで、記述内容そのものには触れていない、ということがないか)を確認すること。

裏付け確認の結果に応じて、以下のいずれかで対応する。

- **完全に裏付ける** → そのまま`primary`/`secondary`として採用。
- **部分的にしか裏付けない**(例:出典1件で2つの主張をカバーしようとしていたが、片方しか支持しない) → 出典を分割し、それぞれが実際に裏付ける範囲だけをラベルに明記する。
- **裏付けを直接確認できない**(検索がJavaScript駆動で結果を直接確認できない等) → `primary`として扱わず`secondary`に格下げし、ラベルに確認状況(例:「要人手検索確認」)を明記する。実在すら確認できない場合は出典として使わない。

この基準は、出典差し替え作業全体で標準として適用すること。

副業の題材での当てはめ(作例): 国税庁の「No.1900 給与所得者で確定申告が必要な人」1件で、「給与所得者で給与以外の所得が20万円以下なら確定申告は不要(条件あり)」と「その場合も住民税の申告は必要」の2つを支えようとする、という状況を考える。このページは所得税の確定申告が必要な人の条件を扱っており、住民税の申告には触れていない。この場合は「部分的にしか裏付けない」に当たるので、国税庁のページは前者だけを支える出典とし、後者は住民税を扱う市区町村等のページを別の出典として立てる。

## 移行方針

- 出典の弱い記事の差し替え作業で、対象記事から順次この形式に移行する。
- 差し替え対象外の記事は、期限を設けず、内容修正の機会があるついでに移行する。
- 記事自動生成プロンプト改訂以降の新規記事は、出典が要る文(`.claude/agents/writer.md` の規則11(6) の線)があるときだけ `sources` を置く。
