# 記事データ受け渡しフォルダ

サブエージェント(ライター・編集長)が作成し、多層判定を通った公開する版を、
サイト本体(Next.js)へ公開するための受け渡し場所です。

## 運用ルール

記事の状態は **作成中 → 公開待ち → 公開済み** の3つで、置き場はこのフォルダの下の同名のフォルダである(2026-10-12 依頼者の決定。「確定稿」という置き場は無い)。段階ごとの置き方は `.claude\skills\run-article-production\SKILL.md` の「記事の状態と置き場」が正。

- `作成中\`: 企画を始めた時点で、記事ごとのフォルダを作る。企画書・原稿・確認メモ・判定の記録・画像のプロンプトは、すべてこの中に置く。中身は git に入れない(`.gitkeep` だけ残す)
- `公開待ち\`: 最後の判定を通り、公開する版ができたら、公開する版の1ファイルだけを置く。`publishAt` を入れる。判定を通っていない原稿は置かない
  - ファイル名: `YYYY-MM-DD_テーマ.md`
- `公開済み\`: 公開の処理(GitHub Actions の公開キュー、または手動の実行)が、公開待ちから移す。担当が新しい記事を手で置くことはしない。サイト本体は、このフォルダだけを `content` へ取り込む。Git commit・pushでVercelが自動デプロイする
- 公開したあとは、作成中のその記事のフォルダを消す(あとで要るものは消す前に報告へ出す)
- 公開済みの記事を直すときは、公開済みの同じファイルを直す。大きく作り直すときは、作成中に作業用のフォルダを作って進め、できた版で公開済みの同じファイルを置き換える
- 判定を通らなかった記事・公開を取りやめた記事は、`非公開アーカイブ\` へ移すか、作成中に残す(公開待ちにも公開済みにも置かない)
