# 2026-08-06 要点メモ: 強調ボックス(callout)・折りたたみ(collapsible)機能の実装

- remark-htmlはデフォルトでsanitizeが有効なため、Markdown本文に`<details>`等の生HTMLを直書きしても消える。charts機能と同じく「frontmatter経由でHTML文字列を組み立て、変換後のHTML文字列に対して文字列置換で挿入する」方式を踏襲すれば、サニタイズを回避しつつ既存の実装パターンとも一貫性を保てる。
- charts挿入で使っていた「見出しブロック直後への挿入」ロジック(afterHeadingとの完全一致判定+splitHtmlBlocksでの分割)は、calloutBoxes/collapsiblesでもほぼ同型だったため、`embedAfterHeading(html, items, renderFn, warnLabel)`という汎用関数に切り出して両方から呼び出す形にした。今後同種の「見出し直後に何かを挿入するfrontmatter項目」を追加する場合もこの関数を再利用できる。
- 一致する見出しが見つからない項目は黙って挿入されない仕様(chartsと同様)。ただしデバッグしやすいよう`process.env.NODE_ENV !== "production"`のときだけ`console.warn`で見出しテキストの不一致を知らせるようにした(本番ビルドのログを汚さない)。
- 動作確認の落とし穴: `content/articles`は`npm run sync-content`(predev/prebuild)によって記事データ確定稿から自動コピーされる生成物であり、手でfrontmatterを編集しても`npm run build`(prebuildが走る)で上書き消滅する。動作確認時は`npx next build`(prebuildを経由しないコマンド)を直接使うか、確定稿側を編集する必要がある。今回は前者を採用した。
- 挿入位置の検証は`npm run build`が通ることの確認だけでは不十分という既存ルール通り、`.next/server/pages/posts/*.json`内の`contentHtml`を実際に読み、対象の見出し直後にcallout-box/article-collapsibleのクラスが出現しているかをスクリプトで確認してから完了とした(記事末尾に意図せず集約される等の不具合がないことを確認済み)。
- CSSはサイト全体で使っている`--color-*`のCSS変数をベースにしつつ、3種のボックス(tip/warning/conclusion)は水色・黄色・緑色で色分けし、`prefers-color-scheme: dark`のメディアクエリでダークテーマ用の配色も追加した(サイト側にダークモード切り替えUIは無いが、OS/ブラウザ側の設定に自動追従する構成)。
